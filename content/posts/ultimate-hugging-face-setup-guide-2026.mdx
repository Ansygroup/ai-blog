## Installing the Hugging Face CLI and Python SDK

The first step is to get the command‑line interface (CLI) and the `transformers` library. On a fresh Ubuntu 24.04 VM, the commands are:

```bash
python3 -m venv hf-env
source hf-env/bin/activate
pip install --upgrade pip
pip install huggingface_hub transformers accelerate
```

The installation completes in **≈3 minutes** on a typical 2‑core VM. The CLI version (`huggingface-cli --version`) should show **0.14.3** or newer, which includes the new `hf login --token` flow that eliminates the need for manual `.huggingface` config files.

**Why the CLI matters:** It lets you push/pull models, datasets, and spaces without leaving the terminal. For instance, uploading a 1.2 GB fine‑tuned RoBERTa model takes **≈12 seconds** with `huggingface-cli upload`, thanks to multipart uploads and automatic checksum verification.

**Common pitfalls:**  
- **Python version:** The SDK requires Python ≥ 3.9. Using 3.8 triggers a `ImportError` in `accelerate`.  
- **Proxy settings:** On corporate networks, set `HTTPS_PROXY` before installing; otherwise the pip download stalls at 0 KB.

## Configuring Authentication and Access Tokens

Hugging Face uses **OAuth‑style personal access tokens (PATs)**. To generate one:

1. Log into https://huggingface.co.  
2. Navigate to **Settings → Access Tokens → New token**.  
3. Choose **Read & Write** for model uploads, or **Inference** for API‑only usage.

After creation, run:

```bash
huggingface-cli login
```

Paste the token when prompted. The token is stored in `~/.huggingface/token`. For CI/CD pipelines, export it as an environment variable:

```bash
export HF_TOKEN=hf_XXXXXXXXXXXXXXXXXXXXXXXX
```

**Security tip:** Rotate tokens every **90 days**. The platform now supports **token scopes**, so you can issue a read‑only token for monitoring services, reducing exposure if a secret leaks.

## Setting Up a Local Development Environment (Docker, Conda)

While a virtual environment works for quick experiments, production teams often rely on Docker for reproducibility. Hugging Face publishes official images:

| Image | Size (CPU) | Size (GPU) | Default Python | CUDA |
|-------|------------|------------|----------------|------|
| `huggingface/transformers` | 1.2 GB | 2.3 GB | 3.11 | 12.2 |
| `huggingface/accelerate`   | 1.0 GB | 2.0 GB | 3.10 | 11.8 |

Pull the GPU image with:

```bash
docker pull huggingface/transformers:gpu
docker run --gpus all -it huggingface/transformers:gpu bash
```

Inside the container, you can verify GPU access:

```bash
python -c "import torch; print(torch.cuda.is_available())"
```

**Performance note:** The GPU image includes **cuDNN 9.2** and **torch‑2.2**, delivering **≈30 % lower latency** on GPT‑NeoX compared to the CPU‑only image.

If you prefer Conda, the `environment.yml` below reproduces the same stack:

```yaml
name: hf-env
channels:
  - conda-forge
dependencies:
  - python=3.11
  - pip
  - pytorch=2.2
  - cudatoolkit=12.2
  - transformers
  - accelerate
  - huggingface_hub
```

Run `conda env create -f environment.yml` and activate with `conda activate hf-env`.

## Deploying Models to Hugging Face Inference API

Once your model lives on the Hub, deploying it to the **Inference API** is a one‑liner:

```bash
huggingface-cli api create \
  --model-id username/awesome-bert \
  --region us-east-1 \
  --hardware gpu \
  --scale 2
```

The command provisions a **GPU‑accelerated endpoint** in the selected region. The first inference call typically warms up in **≈1.2 seconds**, and subsequent calls average **45 ms** for a BERT‑base model on an `nvidia-t4` instance.

**Pricing snapshot (2026 Q3):**

- **Pay‑as‑you‑go:** $0.0005 per token for GPU, $0.0002 for CPU.  
- **Reserved instances:** $199/month for 10 M tokens + dedicated GPU.

**Cost example:** A chatbot handling 5 M tokens per month on GPU would cost **$2,500** (5 M × $0.0005). Adding 10 GB of extra storage is $5/month, negligible at scale.

## Monitoring, Logging, and Scaling Inference Endpoints

Production reliability hinges on observability. Hugging Face integrates with **Prometheus**, **Grafana**, and third‑party services like **Datadog**.

1. **Enable metrics:** Add `--metrics` flag when creating an endpoint.  
2. **Export to Prometheus:** The endpoint exposes `/metrics` with counters for `request_total`, `error_total`, and `latency_seconds`.  
3. **Auto‑scaling:** Set `--scale-min 1 --scale-max 10`. The platform monitors CPU/GPU utilization and scales in 30‑second intervals.

**Case study:** A fintech startup ran 1 M requests in a month. By enabling auto‑scaling, they reduced peak GPU spend from **$4,200** to **$2,800**, a **33 % saving**, while keeping 99.96 % SLA.

## FAQ

### How do I get a free Hugging Face token?
Create an account on huggingface.co, go to **Settings → Access Tokens**, and click **New token**. Choose the **Read** scope for basic model download; select **Write** or **Inference** if you plan to push models or call the API. Tokens are displayed once—copy it immediately.

### Can I run Hugging Face models offline without internet?
Yes. After pulling a model with `transformers` (`model = AutoModel.from_pretrained("distilbert-base-uncased")`), you can disconnect from the internet. For GPU acceleration offline, install the **`accelerate`** package and run `accelerate config` to set the local device map.
