## Downloading & Installing Ollama on Windows

1. **Visit the official site** (ollama.com) and click the Windows “.exe” installer. The file size is ~120 MB.
2. Run the installer as **Administrator**. The wizard automatically adds Ollama to your system PATH and creates a service called `ollama.exe`.
3. After installation, open **PowerShell** and verify the version:  
   ```powershell
   ollama --version
   # Expected output: ollama 0.12.3
   ```
4. **Enable GPU support** by installing the latest NVIDIA driver (minimum 537.13) and the CUDA Toolkit 12.3. During the first run, Ollama detects CUDA and prints:  
   ```
   Detected CUDA 12.3 – GPU acceleration enabled.
   ```
5. **Pull a model** to test the pipeline:  
   ```powershell
   ollama pull llama3:8b
   ```
   Download speed on a 500 Mbps fiber connection averages **1.8 GB/min**, completing in ~4 minutes for the 8‑B model (≈3.2 GB compressed, 6 GB after unpack).
6. **Run a quick inference**:  
   ```powershell
   ollama run llama3:8b "Explain quantum entanglement in two sentences."
   ```
   Expect a response in **≈0.9 seconds** on an RTX 3060.

**Common Windows pitfalls:**  
- If the installer fails with “Access denied,” ensure you have **UAC** disabled temporarily or run the installer from an elevated command prompt.  
- On laptops with hybrid graphics, set the NVIDIA GPU as the **preferred device** in the NVIDIA Control Panel; otherwise Ollama falls back to the integrated Intel GPU, causing a 2‑3× slowdown.

## Installing Ollama on macOS (Apple Silicon)

Apple’s M‑series chips have become the gold standard for local LLM inference thanks to their unified memory architecture. Follow these steps:

1. **Download the .pkg installer** from the Ollama website. The package is signed by Apple, ensuring a smooth Gatekeeper pass.
2. Open the **Installer**, accept the license, and let it copy binaries to `/usr/local/bin`.  
   ```bash
   which ollama
   # /usr/local/bin/ollama
   ```
3. **Install Metal 3** support automatically; no extra SDK is required. Verify with:  
   ```bash
   ollama env
   # Shows: METAL=enabled
   ```
4. **Pull a model** using the built‑in terminal:  
   ```bash
   ollama pull gemma2:7b
   ```
   The download completes in ~2 minutes on a 200 Mbps Wi‑Fi network (≈2.5 GB compressed).
5. **Test inference**:  
   ```bash
   ollama run gemma2:7b "Summarize the plot of Inception."
   ```
   On an M2 Pro, you’ll see a latency of **≈0.6 seconds**, outperforming most Windows GPUs at the same VRAM level.

**macOS‑specific notes:**  
- If you encounter “permission denied” when running `ollama`, run `chmod +x $(which ollama)` to ensure executable rights.  
- For users of **Rosetta 2**, avoid installing the x86_64 version; the native ARM binary is ~30 % faster and uses less power.

## Setting Up Ollama on Linux (Ubuntu 24.04)

Linux remains the preferred environment for developers who need fine‑grained control over GPU drivers and containerization.

1. **Add the official APT repository** (requires `sudo`):  
   ```bash
   curl -sSL https://ollama.com/install.sh | sudo bash
   ```
   This script adds `deb [arch=amd64] https://repo.ollama.com/ubuntu jammy main` and installs `ollama` version 0.12.3.
2. **Install CUDA Toolkit 12.3** (if you have an NVIDIA GPU):  
   ```bash
   sudo apt-get install -y nvidia-driver-560 cuda-toolkit-12-3
   ```
   Reboot after driver installation.
3. **Verify GPU detection**:  
   ```bash
   ollama env | grep CUDA
   # Output: CUDA=enabled
   ```
4. **Pull a model**:  
   ```bash
   ollama pull mistral:7b
   ```
   On a machine with 24 GB VRAM, the download takes ~3 minutes (≈2.9 GB compressed).
5. **Run a test**:  
   ```bash
   ollama run mistral:7b "Write a haiku about autumn in Tokyo."
   ```
   Expect **≈0.8 seconds** latency.

**Linux troubleshooting tips:**  
- If `ollama` cannot locate the CUDA libraries, set `LD_LIBRARY_PATH=/usr/local/cuda-12.3/lib64:$LD_LIBRARY_PATH`.  
- For headless servers, you can run Ollama as a **systemd service**:  
  ```bash
  sudo systemctl enable --now ollama
  ```

## Configuring Model Libraries and GPU Acceleration

Ollama stores models in `$HOME/.ollama/models`. The platform automatically caches compressed blobs and expands them on first use. To fine‑tune performance:

| Setting | Description | Recommended Value |
|---------|-------------|-------------------|
| `OLLAMA_MAX_THREADS` | Number of CPU threads for fallback mode | `8` (or `$(nproc)` on Linux) |
| `OLLAMA_GPU_BATCH` | Batch size for GPU kernels (larger = better throughput) | `32` for RTX 3060, `64` for RTX 4090 |
| `OLLAMA_CACHE_SIZE` | Disk cache limit (GB) | `20` for single 8‑B model, `50` for multiple models |
| `OLLAMA_LOG_LEVEL` | Verbosity of internal logs | `info` (use `debug` only when troubleshooting) |

**Enabling Metal on macOS:**  
Add `export OLLAMA_METAL_BATCH=48` to `~/.zshrc` and restart the terminal. This raises token throughput by ~12 % on M2 Pro.

**Using Quantized Models:**  
Ollama supports 4‑bit GGUF quantization out of the box. Pull a quantized version with the `:q4` suffix:  
```bash
ollama pull llama3:8b:q4
```
Quantized models cut VRAM usage by **≈45 %** while sacrificing less than **0.2 tokens/second** in quality.

## Integrating Ollama with Popular IDEs and APIs

Once Ollama is running, you can call it via its lightweight HTTP API (default port 11434). Below are quick integration snippets for three common environments.

### VS Code (using the “Ollama Assistant” extension)

1. Install the extension from the VS Code marketplace (search “Ollama Assistant”).  
2. In settings, set **Endpoint** to `http://localhost:11434/v1/chat/completions`.  
3. Choose a default model (e.g., `llama3:8b`). The extension now provides inline suggestions, doc‑string generation, and chat windows.

### Jupyter Notebook (Python)

```python
import requests, json

def ollama_chat(prompt, model="llama3:8b"):
    payload = {
        "model": model,
        "messages": [{"role": "user", "content": prompt}]
    }
    resp = requests.post("http://localhost:11434/v1/chat/completions", json=payload)
    return resp.json()["choices"][0]["message"]["content"]

print(ollama_chat("Explain the difference between supervised and reinforcement learning."))
```

### Curl (quick CLI testing)

```bash
curl -X POST http://localhost:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"gemma2:7b","messages":[{"role":"user","content":"Write a 150‑word intro for a blog about AI safety."}]}'
```

**Security note:** By default Ollama binds to `localhost` only. If you need remote access, edit `~/.ollama/config.yaml` and set `bind_address: 0.0.0.0`, then protect the endpoint with an API key.

## FAQ

### How do I install Ollama on Windows 10/11 in 2026?
Download the latest Windows installer from the official Ollama website, run the .exe file, follow the on-screen prompts to accept the license agreement, choose an installation folder, and click Install. After installation, open a Command Prompt and run `ollama --version` to verify the installation.

### What are the system requirements for running Ollama locally in 2026?
Ollama requires a 64‑bit CPU (Intel i5/Ryzen 5 or newer), at least 8 GB RAM (16 GB recommended for larger models), a GPU with CUDA 12+ support for accelerated inference, and 10 GB of free disk space for the core binaries plus additional space for model files.

### How can I download and load a specific LLM model in Ollama?
Use the command `ollama pull <model-name>` (e.g., `ollama pull llama3.1-8b`). Once downloaded, load the model with `ollama run <model-name>` or specify it in your API calls using the `model` parameter. Models are stored in the `~/.ollama/models` directory by default.

### What are the best practices for securing Ollama API endpoints on a local network?
Enable token‑based authentication by setting the `OLLAMA_API_KEY` environment variable, restrict access with a firewall rule that only allows trusted IPs, run Ollama behind a reverse proxy (e.g., Nginx) with HTTPS, and keep the software updated to the latest 2026 release to receive security patches.
