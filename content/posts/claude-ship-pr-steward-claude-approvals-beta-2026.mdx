On 23 November 2026 Anthropic published "Introducing Claude Ship". It is a set of agents that take a pull request (PR) through review, fixes and an approval decision. This article summarizes Anthropic's post, which is linked at the end. We have not tested Claude Ship, so every capability below is Anthropic's description.

## What is Claude Ship?

Claude Ship is three parts working together:

- **Code Review** is already generally available. Anthropic says it reviews a PR "through multiple lenses", adversarially verifies its own findings, categorizes them and posts them on the PR. Each repository can use a Quick, Standard or Deep review level.
- **PR Steward** is new and in beta. It reacts to failing CI checks, merge conflicts and review feedback from Code Review, other tools or teammates. After every push it comments with what it changed and how to undo it. Anthropic says it is designed not to approve or merge PRs. Developers can write `@claude` with an instruction to steer it, or `@claude stop` to make it step back.
- **Claude Approvals** is new and in beta. The team writes an approval policy as a file in the repository. Claude can approve routine changes on its own if the policy allows, and the policy can require human sign-off for other cases. Anthropic compares it to "a smarter CODEOWNERS file". A policy can use Code Review findings or natural-language classifiers as signals.

## How do you turn it on?

There are two routes.

**For developers:** a new `/ship` command in Claude Code. Anthropic says it pushes the change, opens the PR, reviews it and works on feedback and failing checks. What can actually merge still depends on the developer's permissions and the repository's branch rules. `/ship` is rolling out in Claude Code and the desktop app from 23 November.

**For admins:** switch Code Review and PR Steward on per repository. Claude Approvals starts when a connected repository has a policy file on its default branch. Admins set the review level, when reviews run and spend limits. Anthropic says Claude Ship works with existing branch protection and required checks, and recommends running Claude Approvals in observe-only mode first, before making its green light a required check.

## What does it cost, and who can use it?

Claude Ship is available on Claude Team and Enterprise plans, for GitHub repositories. Usage is billed on tokens, so Anthropic warns it can add to an organization's costs, depending on PR count and size, review level, review frequency and how much PR Steward does.

- Admins can set spend limits for Code Review and PR Steward.
- Claude Approvals has no base charge, but classifiers in a policy are billed on the tokens they use.
- A policy that relies on Claude's review triggers a billed Code Review, even in observe mode.
- Running `/ship` counts as regular Claude Code usage.
- Anthropic says eligible Claude Enterprise organizations can claim at least $10,000 in Claude Ship credits, usable within 30 days of claiming, with a claim deadline of 15 January 2027. Terms apply.

It is not available to organizations that use Zero Data Retention, the HIPAA configuration or customer-managed encryption keys.

## What numbers does Anthropic give?

Only one metric, and it is from Anthropic's own team. On the Claude Code team, where Claude's review is one layer of a broader process, Anthropic says merged PRs more than doubled from June to September while the share reverted fell by more than 40%. That is a self-reported figure for one team with its own process. It does not tell you what your repository will see. The post's own image caption also warns that Claude Ship "may miss bugs, security vulnerabilities, or other issues."

## Our take

The interesting part is Claude Approvals. Most teams require a human on every change, and an AI that can sign off on low-risk PRs shifts where review effort goes. That is only as safe as the policy file you write. The observe-only mode Anthropic recommends is the sensible way to find out how often the agent's decision matches your reviewers before you let it gate anything.

Two practical questions to settle before you enable it: who owns the policy file, and what monthly spend limit makes sense per repository.
